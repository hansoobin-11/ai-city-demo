# Baseline v4 장면·타이밍·에셋 추출

`docs/plans/PROJECT-SETUP.md` 첫 구현 체크포인트 1번 결과물이다. 원본은 `reference/baseline/AI CITY 메인 인트로 (오프라인용 v4 · 수동재생).html`이며 이 문서 작성을 위해 읽기만 했고 **원본은 수정하지 않았다**.

## 0. 원본 파일 구조 (읽기 방법 메모)

원본 HTML(507줄, 10.7MB)은 평문 마크업이 아니라 JSON으로 직렬화된 에셋 번들이다. 다음에 다시 열어볼 사람을 위해 구조를 남긴다.

- 507줄 중 대부분은 앱 셸(위저드형 에디터 UI, 디자인 토큰 CSS 등)이고, 실제 콘텐츠는 4개 라인에 집중되어 있다.
- 한 줄(자산 맵)에 `{uuid: {mime, compressed, data}}` 17개 항목이 base64로 들어 있다. `compressed:true`인 항목은 gzip으로 한 번 더 감싸여 있다(HTML 2개, JS 3개). 나머지(이미지 8개, 폰트 1개)는 비압축 base64.
- 다른 한 줄(별칭 테이블)이 각 uuid에 사람이 읽는 이름(`cityDc`, `topDc`, `topLogo`, `detailHc` 등)을 붙인다.
- 셸 자신의 본문(레이아웃 + 재생 컨트롤 + **마스터 타임라인 스크립트**)도 JSON 문자열로 이스케이프되어 한 줄에 들어 있다.
- 디코딩: `base64` → (compressed면) `gzip` 해제 → UTF-8 텍스트. Python `json`/`gzip`/`base64` 표준 라이브러리로 충분하다.

디코딩된 사본은 이 세션의 스크래치패드에만 두었고 저장소 커밋 대상으로는 넣지 않았다(정적 산출물이 아니라 1회성 조사 자료라서). 필요하면 같은 방식으로 재추출 가능하다.

## 3. 카메라 · 전환 스펙

원본 주석(스테이지 하단 안내 문구) 그대로:

> 하나의 5760×1920 캔버스에 공유 transform 적용. A01은 1.32배 근접 뷰에서 전체 파노라마로 줌아웃(약 3.5초). 랜드마크 사이는 3단 아크 무빙(줌아웃 0.84초 → 1.15배에서 팬 1.26초 → 줌인 0.9초, 합 3.0초)으로 이동하며, 카메라가 감속해 멈춘 뒤에야 디테일 레퍼런스가 0.5초 크로스페이드로 들어오고(scale 1.08→1.0, 0.2초 포커스 풀), 다음 이동 전 0.45초 동안 카메라와 같은 방향으로 축소되며 빠집니다. 인접 화면은 같은 변환을 유지하며 어둡게 눌러 도시 맥락을 지킵니다(디테일 이미지를 3면에 늘리지 않음).

코드 상수와의 대응:
- 3단 아크: `PH_OUT=0.28`, `PH_PAN=0.70` (travel 구간 내 진행률 기준 구간 경계). 랜드마크↔랜드마크 travel=3000ms에 대입하면 줌아웃 840ms → 팬 1260ms → 줌인 900ms.
- 디테일 크로스페이드: `FADE_LEAD=150ms`(카메라 정지 전 도입 시작), `FADE_IN=500ms`, `FADE_OUT=450ms`, `FOCUS_MS=200ms`(블러 해소), detail `scale 1.08→1.0`.
- A02→A03 전환은 "converge" 특수 처리: 카메라가 5개 랜드마크 좌표 평균이 아니라 HUB(2880,1030)로 직접 수렴하고, `hubProgress`가 0→1로 올라가며 수렴 라인(4절)이 함께 나타난다.
- RD→A02 재전환(`prepareRelight`)은 스마트로드 클로즈업의 단일 센서를 먼저 정리(0.55초 페이드아웃)한 뒤 A02에서 5개 센서를 처음부터 다시 점등한다.
- OUTRO→LOOP는 `dayPhase`를 1→0으로 되돌리며 A01 인트로의 야간 톤으로 복귀.

## 4. 랜드마크(센서) 고정 좌표 · A03 수렴 라인

5760×1920 공유 캔버스 절대좌표(`cityDc.html`의 `DOMAINS`/`PATHS`):

| key | 라벨(EN/KO) | 좌표(fx,fy) | 계열 |
|---|---|---|---|
| `hc` | AI HUMAN CARE / 사람의 건강과 돌봄 | 700, 720 | warm |
| `sf` | AI SAFETY / 건물·시설 안전 | 3000, 780 | warm |
| `inf` | AI INFRASTRUCTURE / 핵심 시설·자원 관측 | 4700, 800 | cool |
| `rb` | AI ROBOTICS / 현장 로봇 운영 | 4850, 1330 | cool |
| `rd` | AI SMART ROAD / 도로 인프라 관리 | 1750, 1400 | warm |

HUB(중앙 허브) = (2880, 1030). 각 랜드마크에서 HUB까지 2단 3차 베지어(고정 제어점, 원본 그대로 — "지오메트리는 고정이므로 모듈 로드 시 1회만 계산"):

```
hc : [700,720]  → C(1300,720, 2100,810, 2500,900)  → C(2660,940, 2770,1000, 2880,1030)
sf : [3000,780] → C(3030,835, 3010,905, 2950,955)   → C(2915,985, 2890,1015, 2880,1030)
inf: [4700,800] → C(4500,850, 3900,850, 3350,905)   → C(3150,940, 2980,995, 2880,1030)
rb : [4850,1330]→ C(4300,1390,3650,1320,3250,1180)  → C(3070,1120,2970,1060,2880,1030)
rd : [1750,1400]→ C(2150,1450,2500,1300,2660,1160)  → C(2750,1090,2810,1050,2880,1030)
```

색상: warm = core `#FF8A66` / glow `#FF6A47`, cool = core `#7FE3EE` / glow `#3FD3E8`. A03에서는 5개 마커 강도를 0.25로 낮추고 라벨을 숨기며(`labelVisible: !connectionMode`), 이 5개 경로를 따라 입자(도트)가 HUB로 흘러들어간다.

## 5. A02 "5개 신호 완성" 점등 순서

A02 체크포인트의 hold(3000ms) 안에서 `sensorStep=240ms`, `sensorFade=170ms`로 **순서대로** 켜진다. 점등 순서는 배열 `order=[0,1,2,3,4]` = **hc → sf → inf → rb → rd** (랜드마크 개별 체크포인트가 등장한 순서와 동일). i번째 센서의 세기는 `smooth((held - i*240) / 170)` — 즉 하나가 살짝 켜지는 도중 다음이 시작해 리듬감 있게 이어진다.
