# 프로젝트 작업 흐름

## 항상 적용

1. 규모 있는 변경은 구현 전에 범위, 변경 파일, 검증 방법을 계획으로 제시하고 승인을 기다린다.
2. 한 단계에서 한 가지 목표만 처리한다. 승인 없이 다음 단계로 넘어가지 않는다.
3. 원본 디자인 파일과 솔루션 자료는 읽기 전용으로 취급한다.
4. 요청받지 않은 기능, 카피, 카메라 움직임, 외부 연결을 추가하지 않는다.
5. 긴 작업에서 도구 호출이 연속되면 무엇을 왜 확인하는지 중간에 설명한다.
6. git 상태나 구현 상태를 말하기 전에 실제 파일과 명령 결과를 확인한다.
7. 리뷰와 실제 반영은 분리한다. 검토 요청만 받았다면 코드를 수정하지 않는다.

## 단계 완료 보고

- 변경 파일
- 구현 범위
- 직접 실행한 검증과 결과
- 사용자가 실제 포터블 모니터에서 확인할 항목
- 다음 단계에서만 다룰 내용
