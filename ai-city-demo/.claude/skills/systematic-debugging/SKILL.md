# 전시 UI 디버깅

## 원칙

증상을 재현하고 근본 원인을 확인하기 전에는 수정하지 않는다.

## 절차

1. 사용자가 신고한 동일한 브라우저, 실행 방식, 입력 장치와 가장 가까운 조건에서 재현한다.
2. 콘솔 오류와 현재 화면 상태, 활성 타이머, 선택된 솔루션, 포인터 종류를 확인한다.
3. 잘 동작하는 유사 흐름과 실패 흐름의 차이를 나열한다.
4. 원인을 한 문장으로 가정하고 가장 작은 변경 하나로 검증한다.
5. 같은 재현 시나리오로 수정 전후를 비교한다.
6. 세 번의 수정 시도 후에도 실패하면 추가 패치를 멈추고 상태 구조나 실행 방식을 재검토한다.

`file://`과 localhost 결과를 섞어 판단하지 않는다. 터치 문제를 데스크톱 마우스 에뮬레이션만으로 해결됐다고 결론내리지 않는다.
