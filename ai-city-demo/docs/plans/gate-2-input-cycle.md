# 게이트 2 — 입력과 자동 카드 순환 (완료)

## 확정 사항

- 마우스: hover 즉시 카드 표시, 클릭(pointerup) 즉시 진입 신호
- 터치/펜: **1탭 = 카드 표시(무장), 같은 핫스폿 2탭째 = 진입 신호** (사용자 확정)
- 자동 순환 1.5초 간격 (원본 값 유지), 사용자 입력 즉시 정지, 이탈 900ms 후 재개
- 진입 신호 후 400ms 잠금 — 중복 입력 차단

## 구현

- `src/lib/city-interactions.ts` (신규) — 포인터 이벤트 바인딩, 순환 타이머, 상태 관리를 전담
- `PointerEvent.pointerType`으로만 분기(`mouse` vs 그 외). `navigator.maxTouchPoints` 등 장치 단위 분기 없음
- 실제 상세 화면 전환은 아직 없음. `city:enter-zone` 커스텀 이벤트만 발생 (게이트 3에서 소비)
- `.zone__bridge` 추가 — 핀과 카드 사이 빈 구간에서 마우스 hover가 끊기지 않도록 잇는 투명 영역
- `.zone`의 `pointer-events: none` 해제, `touch-action: manipulation` 적용
- `data-active` 속성으로 hover/터치무장/자동순환 강조를 통합 (원본의 `isActive` 로직과 동일한 우선순위)

## 추가 조정 — 속도·오퍼시티 (사용자 피드백 반영)

"이동이 빨라서 정신없다"는 피드백에 따라 다음을 조정했다. 정답이 정해진 값이 아니라
현장에서 보고 더 조정 가능하다.

| 항목 | 이전 | 이후 |
|---|---|---|
| 자동 순환 간격 | 1.5초 | 3.2초 |
| ring/ping 테두리색 전환 | 0.85s | 1.6s |
| 라벨 색상 전환 | 0.85s | 1.6s |
| 글로우 전환 + 피크 오퍼시티 | 0.85s / opacity 1 | 1.6s / opacity 0.85 |
| 쉐브론 전환 | 0.3s | 0.7s |
| 카드 전환 | **없었음(스냅으로 나타남)** | opacity 0.6s, transform 0.7s 추가 |

카드에 트랜지션이 누락되어 있던 것을 이번에 발견해 같이 고쳤다. 이게 전환이
급하게 느껴진 원인 중 하나였을 것으로 보인다.

## 추가 조정 — 핫스폿 디자인 통일 + 카드 materialize 전환 (사용자 요청)

"각 핫스폿 활성 시 Human Care랑 디자인 다 맞춰줘" 요청에 따라, Human Care에만
있던 강조 스타일을 5개 전 영역의 기본 스타일로 승격했다. 이제 `accent` 구분이
없어져 5개 핫스폿이 완전히 동일한 시각 처리를 받는다.

| 항목 | 이전(Human Care만) | 이후(5개 전부) |
|---|---|---|
| 원 표식 지름 | 60px (다른 4개는 56px) | 60px |
| 핑 링 inset / 코어 inset | -8px / 21px (다른 4개는 -6px/20px) | -8px / 21px |
| 글로우 box-shadow | 26px, alpha .95 (다른 4개는 22px/.9) | 26px, alpha .95 |
| 카드 테두리 | 코랄(다른 4개는 흰색) | 코랄 |
| 카드 eyebrow 색상 | 코랄(다른 4개는 흐린 흰색) | 코랄 |

`src/data/zones.ts`의 `accent` 필드를 제거했고, `city.css`의 `[data-accent="true"]`
규칙은 전부 기본 규칙으로 병합했다.

카드 전환은 "흐릿하게 풀렸다가 나타나는" 느낌으로 다시 짰다: opacity·filter(blur)·
transform(이동+스케일)을 함께 전환한다.

```
숨김: opacity 0, filter blur(6px), translateY(±10px) scale(0.97)
활성: opacity 1, filter blur(0),   translateY(0)     scale(1)
전환: opacity/filter 0.6s, transform 0.7s
```

각도 재조정 필요 시(블러 강도, 스케일 정도) 알려주면 바로 조정 가능.
